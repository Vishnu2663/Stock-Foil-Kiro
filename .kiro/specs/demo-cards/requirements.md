# Requirements: demo-cards
Ready-made demo cards so a judge can test the real Payday scanner in about a minute, with or without a printer. Every
file is generated by this app's own code (card generator, printable sheet, photo simulator, PDF writer) and checked
by the real scanner in a test, so the expected result written in the guide is guaranteed.

## R1 One story
1. THE SYSTEM SHALL use one story for every demo card: worker Ramesh, employer Vishnu Builders, ₹700 a day, advance
   ₹100, November 2026, fixed card ids and fixed pairing secrets, so the files are reproducible.

## R2 The sets (folder demo-cards/)
| Folder | Files | Scenario | Expected |
|---|---|---|---|
| 1-genuine | stock.jpg, foil.jpg | both halves punched together: 22 days, 2 advances | genuine pair, 22 days, ₹15,200 |
| 2-extra-hole | stock.jpg, foil.jpg | the same card with one extra day on the worker half only | genuine, disputed: that day flagged, not paid |
| 3-wrong-half | stock.jpg, foil-from-another-card.jpg | a worker half and a foil from a different card | not a pair: rejected |
| 4-two-shifts | stock.jpg, foil.jpg | two circles per day; 20 full days and 1 half day, 1 advance | 20½ days, ₹14,250 |
| print | blank-card.pdf, blank-card.png | the real printable A4 sheet, unpunched | to print, cut, punch and scan |
| print | punched-genuine.pdf | the set-1 card, one half per page, cut out on a dark background, holes as dark discs | to show on a screen (or print) and scan with a phone |

## R3 Images
1. Photos SHALL come from the photo simulator with mild camera settings (rotation ≤ 10°, slight blur and noise, even
   light, dark table), about 1600 px on the long side, JPEG quality 88, under 1.5 MB each, with the card's printed text.
2. The guide SHALL label every image "generated by the app's photo simulator", not a real photograph.

## R4 Generator
1. `npm run demo:cards` SHALL write every file above and demo-cards/expected.json (verdict, days, half days, advances,
   amount, disputed days per set).
2. It SHALL be deterministic: running it twice on the same machine gives identical files.
3. It SHALL use only the project's existing dependencies (Vite runs the TypeScript; headless Chrome renders the sheet
   with its text and runs the app's own PDF writer).

## R5 Verification
1. tests/demoCards.test.ts SHALL decode each JPEG, scan each half with scanImage, verify each pair with verifyPair and
   assert the result equals expected.json.
2. It SHALL render the punched-genuine pages to pixels from the same page geometry and confirm they read as set 1.
3. IF a file does not scan as expected THEN the generator settings SHALL change, never the scanner.

## R6 Judge's guide (demo-cards/README.md)
Headings, in order: Try Stock & Foil in 1 minute · What's in this folder · Option A: No printer (upload the photos) ·
Option B: Scan with your phone camera · Option C: The real thing (printer and hole punch) · Expected results ·
Tips if a scan does not work · How these files were made. Screenshots of the result for set 1 and set 2.
Nothing in it claims more than the tests prove.
